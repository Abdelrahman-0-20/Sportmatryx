# Sportmetryx Football — full data export

Every table from the project database, exported to CSV. Generated locally from
the seeded demo database (same data you see at localhost:3000).

## Honesty note (spec §25)
All of this is **synthetic demo data** generated by `prisma/seed.ts` — no real
athletes, no real observations. Demo accounts all use the password
`Demo-SMX-2024!` (password hashes redacted here).

## Files

| File | Rows | What it is |
|---|---|---|
| `user.csv` | 6 | Demo accounts (admin/performance/medical/coach/executive/athlete). Password hashes redacted. |
| `session.csv` | 1 | Auth sessions (token hashes redacted). |
| `account.csv` | 0 | OAuth accounts (unused). |
| `team.csv` | 3 | Demo squads. |
| `teamMembership.csv` | 6 | User ↔ team assignments. |
| `athlete.csv` | 50 | The synthetic roster (IDs, names, positions, birth year, baseline refs). |
| `consentRecord.csv` | 50 | Per-athlete consent states (WITHDRAWN / GRANTED etc. — drives validity gates). |
| `positionConfiguration.csv` | 6 | Position-room display configuration. |
| `device.csv` | 6 | Registered data-capture devices. |
| `calibrationRecord.csv` | 6 | Device calibration snapshots. |
| `observation.csv` | 19,732 | The core synthetic measurement rows (HR, HRV, RHR, load, sleep, environment…). |
| `dataSource.csv` | 5 | Where observations claim to originate. |
| `importJob.csv` | 2 | CSV import jobs processed by the app (source of marketplace "import package" products). |
| `trainingSession.csv` | 350 | Practice/game sessions. |
| `footballContext.csv` | 350 | Per-session football context (drill vs game, opponent, surface…). |
| `athleteBaseline.csv` | 50 | Per-athlete own-baseline (p10/p50/p90) used for normalization. |
| `baselineObservation.csv` | 450 | The observations feeding each baseline. |
| `performanceModel.csv` | 1 | Scoring model definition (7 weighted components). |
| `modelConfigurationVersion.csv` | 1 | Version/config of the scoring model. |
| `performanceScore.csv` | 682 | Composite 0–100 scores with band + confidence + validity state. |
| `scoreComponent.csv` | 4,774 | The 7 component values behind each score. |
| `scoreDriver.csv` | 3,039 | Explainability drivers ("why this score"). |
| `validityCheck.csv` | 3,422 | Fail-closed validity gates per score (consent, freshness, sample integrity…). |
| `intervention.csv` | 6 | Intervention queue items. |
| `interventionReview.csv` | 4 | Reviewer decisions on interventions. |
| `report.csv` | 2 | Generated reports. |
| `auditLog.csv` | 1 | Audit-chain entries (hash-chained). |

## Re-export anytime

```bash
node data-export/export.mjs        # exports the local database
DATABASE_URL="<neon-url>" node data-export/export.mjs   # exports the Neon cloud database
```

Redacted fields (never exported in real form): `passwordHash`, `tokenHash`,
`accessToken`, `refreshToken`, `idToken`.
