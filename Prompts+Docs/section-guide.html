Sportmetryx Football — Section Guide

What every section of the platform does, the benefit it delivers, and how to use it in daily work.

1 · Access & Accounts

Landing Page /

What it is Public overview of the platform: the scoring model (READY / MONITOR / COMPROMISED), module map, and trust/audit principles.
Benefit New users understand the product before signing in; stakeholders can share a single link for demonstrations.
How to use Read the module cards, then use Sign in (existing account) or Continue as guest (read-only preview with synthetic data).

Sign In /login

What it is Secure email + password login with role-based access control (RBAC). Sessions are cookie-based and server-verified.
Benefit Each role sees only what it should: no cross-role data leakage, auditable access.
How to use Enter any demo account (e.g. coach@demo.sportmetryx.dev) with password Demo-SMX-2024!. Guests can use the guest link without an account.

Guest Mode /guest

What it is Read-only mode using synthetic sample data when you have no account (or the database is unreachable).
Benefit Investors, parents, or new staff can explore the full UI with zero risk to real data.
How to use Click Continue as guest on the landing page. All write actions (checkout, interventions) stay disabled and clearly labeled.

Admin Console /admin

What it is Administrator workspace for users, sessions, and system integrity (audit chain verification).
Benefit One place to provision accounts, audit activity, and confirm the tamper-evident audit log has no breaks.
How to use Sign in as admin@demo.sportmetryx.dev, review the user table, and run the audit-chain check to verify record integrity.

2 · Performance Core

Roster /roster

What it is Searchable squad list with each athlete's current readiness band (READY ≥ 70, MONITOR 40–69, COMPROMISED < 40, or WITHHELD).
Benefit Coaches spot at-risk athletes in seconds instead of scanning spreadsheets.
How to use Filter by band or name; click any athlete row to open their full profile. Sort by readiness to triage training groups.

Athlete / Player Profile /player/[id]

What it is Deep individual view: score components, evidence quality (confidence), validity gates, history, and consent status.
Benefit Explains why an athlete scores as they do — never a black-box number; builds trust in decisions.
How to use From the roster, open a player. Review component breakdown, check any WITHHELD reason (e.g. missing consent, stale baseline), then act in Team Command.

Team Command /team-command

What it is Squad-level command center: aggregated readiness, distribution across bands, and priority call-outs.
Benefit Answers the daily question "who do I push, who do I protect?" in one screen.
How to use Each morning, scan COMPROMISED/MONITOR lists, open flagged athletes, and plan the day's adjustments from there.

Game Readiness /game-readiness

What it is Match-day readiness projection per athlete, combining recent load, recovery, and score trend.
Benefit Objective input for selection meetings — pick the squad on evidence, not gut feel.
How to use Before match day, review projected readiness per position; discuss borderline athletes with the performance staff.

Position Room /position-room

What it is Readiness and scoring grouped by playing position (GK, DEF, MID, FWD).
Benefit Unit coaches see their own group in context; positional load differences become visible.
How to use Select a position tab to compare your unit; use it in unit-specific planning meetings.

Practice Command /practice-command

What it is Training-session view: who is ready to train fully, who needs modification, today.
Benefit Prevents overtraining — modifies sessions before injuries happen, not after.
How to use Check before each session; athletes in MONITOR/COMPROMISED get modified loads per the recommendations shown.

Recovery Command /recovery-command

What it is Recovery status overview: sleep, soreness, and recovery-trend signals feeding the score.
Benefit Makes recovery a managed resource, equal to training load.
How to use Review after heavy blocks; schedule extra recovery for athletes trending down across several days.

3 · Care, Data Quality & Context

Interventions /interventions

What it is Create and track care actions (load reduction, medical referral, recovery protocol) linked to athlete scores.
Benefit Closes the loop: a risk signal leads to a documented action with a follow-up — nothing falls through the cracks.
How to use From a flagged athlete, open an intervention, choose the type and note, save; track its state until resolved. Every action is written to the audit log.

Data Quality /data-quality

What it is Validity gates dashboard: calibration freshness, sample integrity, timestamp freshness, baseline sufficiency, consent state.
Benefit Shows which data can be trusted today — scores fail closed when evidence is weak, so no decision rests on bad data.
How to use Review weekly; re-run imports or recalibrate devices for any gate shown as failing.

Environment & Travel /environment-travel

What it is Context layer for heat, travel, and scheduling factors that affect performance outside of training itself.
Benefit Separates "he is declining" from "he played in 35°C heat" — fairer evaluations, better trip planning.
How to use Around travel weeks, check environmental load alongside readiness to adjust expectations and plans.

Research /research

What it is Aggregate, anonymized analytics for sports-science staff: cohort trends and model calibration checks.
Benefit Turns months of session data into insight — validate the scoring model and find cohort patterns.
How to use Select a cohort and time range; export results for reports. Individual identities are never exposed here.

Digital Twin Simulation /player/[id]/twin

What it is "What-if" simulator: replay a training block with modified load and see the projected score outcome.
Benefit Test decisions safely — try a lighter week before committing to it in real life.
How to use From a player profile, open the twin, adjust the load parameter, run the simulation, and compare projected bands.

4 · Marketplace (Demo Commerce)

Marketplace Listing /marketplace

What it is Catalog of data products: team data exports (derived from real import jobs) and synthetic sample datasets. Sellers can create listings with multiple product photos.
Benefit Shows the commercial layer of the platform — how data could be packaged and sold — with full honesty labels (every item is marked DEMO / synthetic).
How to use Browse or filter by tag, data type, and availability; search by name; open a product card for details and source summary; download a labeled sample CSV before "buying".

Sell a Product /marketplace/sell

What it is Listing creation form: name, description, price, and multiple image uploads with previews and re-ordering.
Benefit Team staff can package their own data products for sale — the marketplace becomes a two-sided store.
How to use From the marketplace, open Sell; fill the form, drag/select several photos (first image becomes the cover), and publish. Images are stored on the server; uploads are validated by type and size.

Cart & Checkout /marketplace/cart

What it is Shopping cart with automatic calculation (price × quantity per line, grand total) and a demo checkout flow.
Benefit Complete commerce UX without touching real money — ideal for demos and stakeholder reviews.
How to use Add products with Add to cart (the floating cart dialog shows live totals); open the full cart page, adjust quantities, then Check out. The checkout re-prices every item server-side and records a MARKETPLACE_DEMO_PURCHASE entry in the tamper-evident audit log. No payment processing, no money moved — always labeled demo.

5 · The Scoring Model (Behind Every Screen)

How scores are built

Method Seven weighted components (fitness, load, recovery, sleep, soreness, readiness signals, context) normalized against each athlete's own baseline percentiles (p10 / p50 / p90).
Benefit Every athlete is measured against themselves, not the squad average — a 65 for a returning-injury player means something different than for a starter.
Bands READY ≥ 70 · MONITOR 40–69.9 · COMPROMISED < 40 · WITHHELD when evidence is insufficient.

Validity gates & audit trail

Method Scores fail closed: if calibration is stale, consent is missing, samples are incomplete, or timestamps are old, the score is WITHHELD with an explicit reason.
Benefit The platform never presents a confident number built on weak evidence — this is the core trust guarantee.
Transparency Every sensitive action (purchases, interventions, consent changes) is written to a SHA-256 hash-chained audit log that anyone can verify for tampering.
